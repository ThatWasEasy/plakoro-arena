# PLAKORO ARENA
遊玩網址：https://shawnlin0201.github.io/plakoro-arena/dist/
支援版本：預組 01-09，探險隊 01。（共 15 隻寶可夢、126 個招式）

# 目前功能主要包含了
- 雙人對戰：基本上與 PLAKORO 原先規則相同，主要是用來輔助玩家對戰遊玩
- 單人爬塔：享受基於 PLAKORO 規則所改編的 Rougelike 遊戲，至少需要一組預組才能遊玩
- 模擬組骰：離線試組能量骰，可 3D 擲骰、比較兩組骰子、查看能量組合機率與各招式成功率，並推算組出這組骰要買哪些商品
- 店家資訊：查看店家地圖、賽事行事曆與店家清單
- 賽事工具：瑞士制與單淘汰的配對、成績登錄、排名與抽獎轉盤

# 單人爬塔
> 『踏上 PLAKORO 的冠軍之路！』你將在旅途中遇到其他訓練家，從戰鬥中逐步累積經驗並強化 PLAKORO 的能力，打敗三大天王贏得 PLAKORO 冠軍！

## 與 PLAKORO 不同的是
- 初始狀態只擁有一顆能量骰子與兩樣招式
- 招式學習耗能不超過當下骰子數量 * 2
- 電腦執行招式：替電腦丟角色骰+關卡數量的骰子（ex: 第一關只丟一個），並只看能量數量不看能量顏色。

## 在戰鬥過程中你可能會遇到
- 戰鬥：與其他電腦訓練家對戰並獲得經驗值。
- 事件：各種與寶可夢相遇的事件，有機會強化你的 PLAKORO
- 篝火：回血回血！休息是為了走更長遠的路。

## PLAKORO 成長方式
戰鬥：過程中累積經驗值後可以從攻擊/防禦/HP 上限擇一增加
打敗天王：獲得新的招式

## 無法出招時
爬塔起手只有兩招，可能遇到「一招被對手封印、另一招是上回合剛用過」而無招可出的情況（招式滿四招時不會發生）。此時招式面板會出現「跳過這回合」按鈕，跳過後下一回合即恢復可用。電腦遇到相同狀況時也會跳過該回合。

# 模擬組骰
> 離線試組屬於自己的能量骰，測試不同搭配下的擲骰結果與機率分布。

## 能量骰構造
一顆完整能量骰由兩個半顆組成：
- 2 面固定類型（無法更改）：凸面固定為草/火/水/雷/鋼其中一種，凹面固定為惡/鬥/超/飛其中一種
- 2 個圓槔：插單能量晶片（任意一種類型）
- 2 個方形槔：插雙能量晶片（可選兩種類型，斜線分半，也可以相同）

## 組骰功能
- 點擊任一面即可開啟能量選擇視窗調整該面能量
- 骰子2、骰子3可勾選「與骰1相同」，之後骰子1的任何調整都會即時同步過去
- 快速套用純屬骰：一鍵把圓槔、方槔（含凸面或凹面，依所選能量所屬固定池而定）全部換成單一屬性
- 新增一組骰子來比較：可再開一組「骰組 B」（建立時複製骰組 A），之後機率表與招式機率都會並列顯示兩組數字，用來比較「改一個面差多少」

## 模擬擲骰
- 3D 擲骰：真實物理模擬（Three.js + cannon-es）的擲骰台，按住畫面聚攏骰子、拖曳搖晃、放開擲出，由骰子實際落地的面決定結果
- 快速擲骰：略過動畫直接取得結果

## 結果機率表
整理三顆骰子一起擲的 216 種面組合，依「最終集齊的能量組合」統計機率並降序排列。
- 只看：複選特定能量來篩選組合
- 依數量排序：把相同能量數量的組合分組彙總（可收合展開查看細項）
- 顯示累計機率／顯示恰好機率：在分組模式下切換。「恰好 N 個」是剛好擲出該數量的機率，「N 個以上」是累計機率（例如招式需要 3 個火，能付得起的是「3 個以上」而不只是剛好 3 個）
- 顯示次數：勾選後除了百分比也顯示 `n/216` 的次數

## 招式機率
選一隻寶可夢，列出牠**所有**招式在目前骰子配置下的成功率（能湊出招式所需能量的機率）。
- 「無色」需求可由任何能量支付，其他屬性則必須由該屬性支付
- 參與擲骰：可個別設定每顆骰要擲幾次（有些規則允許同一顆骰擲多次），機率會依總擲骰次數重算
- 角色骰效果標示於卡片下方，顯示的是**累進機率** —— 招式要先成功才會進行角色骰判定，所以是兩者的聯合機率（例如招式 80%、角色骰 3/6，實際發動為 40%）
- 有骰組 B 時，每個招式都會並列顯示兩組的機率

## 購入零件
組骰頁按「購入零件」，把目前這組骰換算成要買的商品。
- 需要哪些零件：凸面／凹面／單晶片／雙晶片逐項列出。單一屬性骰必然有一個廢面（凸面只能是草火水雷鋼，凹面只能是惡鬥超飛），那一面標示為「任意」，任何半骰都可以
- 我已擁有：以「盒」為單位登記，不必去數手上有幾個晶片。可摺疊，依啟程／探險／DX 分組，點商品名會跳出該盒的內容物
- 還需要購買：扣掉庫存後，用精確搜尋（非貪婪近似）算出最省的組合。只推薦當下已發售的商品；若等某個未發售商品上市會更省，會另外提示
- 盡量分散套組：只在同價的答案之間挑更多不同的盒，不會讓花費變高

商品內容物來自 [pla-koro.com](https://pla-koro.com) 對官方商品照的點算，每盒的單晶片＋雙晶片數與盒上印的「改裝晶片 ×18」一致。

# 店家資訊
- 地圖：可遊玩／販售店家的 Google 我的地圖
- 行事曆：賽事與活動行程
- 店家清單：從 Google 試算表讀取，可依「類型」標籤複選篩選（多選為 AND 條件）

# 賽事工具
主辦方用的配對與計分工具，資料存在瀏覽器 localStorage。
- 賽制：瑞士制（積分組配對、官方 OMW%／OOMW% 破同分）或單淘汰
- 成績登錄：瑞士制任一輪都能改，排名會即時重算；已配對的對戰不會被重排，與實際賽事作法一致
- 退回輪次：兩種賽制都能退回某一輪重排，確認框會先說明會刪掉幾輪幾場。單淘汰改動舊成績只能走這條路，因為後續輪次的參賽者就是前一輪的勝者
- 名冊異動：中途加入或退賽。退賽是標記而非刪除 —— 他打過的比賽影響對手的 OMW%，刪掉會讓別人的名次憑空改變。中途加入可選擇直接排入當前輪（補上輪空位）或下一輪
- 手動調整配對：點兩位選手對調位置，或指定由他人輪空
- 抽獎轉盤：從參賽者中抽獎，可勾選參加資格

## 匯出與匯入
賽事只存在該台瀏覽器的 localStorage，所以在場邊用手機跑的賽事，回家的電腦看不到。一場賽事匯出成**一個 JSON 檔**，帶著走或留存。

- 匯出：選手、每輪配對、每場成績都在同一個檔裡，下載或複製文字皆可。檔名如 `20260904-秋季賽.json`
- 匯入：可一次選多個檔。每個檔各自判斷，壞掉的那個會列出原因，不影響其他檔
- 匯入會產生新的賽事 id，所以同一個檔匯兩次會得到兩場，不會覆蓋既有的。多的刪掉是一個動作，被覆蓋的成績救不回來

檔案格式刻意寫成人看得懂的樣子 —— 對戰直接寫選手名字而非內部 id，方便離線整理或用別的工具處理：

```json
{
  "format": "plakoro-tournament",
  "version": 2,
  "name": "秋季賽",
  "date": "2026-09-04",
  "venue": "台北",
  "system": "swiss",
  "players": [
    { "name": "小明", "code": "P000001" },
    { "name": "小美", "dropped": true }
  ],
  "rounds": [
    { "round": 1, "matches": [
      { "table": 1, "a": "小明", "b": "阿華", "winner": "小明" },
      { "table": 2, "a": "小美", "b": "阿銘", "draw": true },
      { "a": "阿杰", "bye": true }
    ]}
  ]
}
```

沒打完的對戰就沒有 `winner` 也沒有 `draw`。`code` 是跨賽事追蹤同一個人用的選手代碼，選填，可在建立賽事時用 `小明;P000001` 一起輸入。同一場若有兩位同名選手，第二位在檔案中的參照會是 `小明#2`，匯回來仍是兩個人。

# 開發
```bash
npm install
npm run dev          # 開發伺服器
npm run build        # 建置到 dist/
npm run fetch-data   # 從 Supabase 重新抓取角色與招式資料到 src/data/generated/
```

多語系（日／英／繁中）：介面文字在 `src/i18n/locales/`，寶可夢與招式名稱的翻譯在 `src/data/translations/`（以日文為基底，缺少翻譯時自動顯示日文原文）。

## 本機資料庫

選手資料／賽事紀錄要搬上資料庫（規劃見 `docs/data-model.md`）之前的本機開發環境，與現在上線的靜態網站完全無關，純粹是本機驗證用。

```bash
cp .env.example .env   # 第一次使用時
npm run db:up          # 在 plakoro-arena-api repo 裡執行
npm run db:migrate      # 套用 db/migrations/ 底下的 schema
npm run db:psql         # 開 psql 互動視窗
npm run db:down         # 關閉（資料還在 volume 裡，下次 db:up 會接著用）
```

GUI：`npm run db:up          # 在 plakoro-arena-api repo 裡執行

新增 schema 變更：在 `db/migrations/` 底下加一個新檔（例如 `0002_xxx.sql`），不要改已經套用過的舊檔——`db/migrate.mjs` 用 `schema_migrations` 表記錄套用過哪些檔案，照檔名順序只套用沒套用過的。

## `backup/`

不進 git 的筆記放這裡（含密碼之類不該公開的機制說明），`.gitignore` 已經排除，自己手動備份。

## API server

`server/`，登入／註冊用，獨立於前端的 Vite dev server。不接 LINE／email／任何 OAuth——玩家是「編號 + 自己設的 PIN」，忘記 PIN 就跟第一次一樣找主辦要一組新的認領碼重設。

```bash
npm run server:dev   # 開發用，存檔自動重啟，預設聽 :8787
```

| Endpoint | 用途 |
|---|---|
| `POST /api/auth/register` | 全新玩家：`{name, pin}` → 自動配編號，直接可用 |
| `POST /api/auth/claim` | 既有編號玩家：`{code, claimCode, pin}` 接回歷史紀錄，設自己的 PIN |
| `POST /api/auth/login` | `{code, pin}` → 換一個新的 session token |
| `GET /api/players/me` | 帶 `Authorization: Bearer <token>` 查自己的資料 |
| `POST /api/admin/claim-codes` | 主辦專用，帶 `X-Admin-Secret` header，`{code}` → 產一組一次性認領碼，拿去怎麼發給那位選手都行 |

`.env` 裡要多設 `AUTH_SECRET`（簽 session token 用）跟 `ADMIN_SECRET`（保護上面那個主辦端點），`.env.example` 有放預設值但正式環境記得換成亂數字串，不要照抄。

### 換一台機器開發

Schema 本身已經在 git 裡（`db/migrations/`），換機器只要重新跑一次 `db:up` + `db:migrate` 就有相同的空白資料庫，不需要另外同步。

如果連同目前測試用的資料列也想一起帶過去：

```bash
npm run db:dump      # 匯出目前這台的資料（含 schema）到 db/dump.sql
# 把 db/dump.sql 傳到另一台機器（AirDrop／隨便一個雲端硬碟都行，這個檔案故意不進 git，
# 因為裡面可能是你隨手測試用的假資料，沒有進版控的必要）
npm run db:up          # 在 plakoro-arena-api repo 裡執行
npm run db:restore    # 直接 restore，連 schema 一起回來，不用先跑 db:migrate
```

### 之後要上到正式機器

現在還沒有後端程式、也還沒選 PaaS，先說會怎麼接上去：`db/migrate.mjs` 認的是環境變數 `DATABASE_URL`，本機用 `.env` 裡那組指向 docker 的 Postgres，正式環境只要換成 PaaS 給的那組連線字串（`DATABASE_URL=postgres://...` 設成該平台的環境變數），同一支腳本原封不動 `npm run db:migrate` 就能把 schema 套到正式的資料庫上——不用另外寫一套。之後接 API server 時，連線方式也是同一個 `DATABASE_URL`。

正式環境的 DB 不會用 `docker compose`（那只是本機的容器），而是 PaaS 平台自己託管的 Postgres；真的要用 GUI 檢查正式資料時，平台通常自帶一個，或者把 pgweb 指向那組 `DATABASE_URL` 臨時開一下（記得正式環境大多要 `sslmode=require`，跟本機的 `sslmode=disable` 不同）。

資料庫的部分欄位含有多餘空白（例如招式 `STW05-002` 的 id 尾端有換行字元），且無權限在 Supabase 端修正，因此 `useCharacterData.js` 於讀取時會自動修剪所有用於比對與查找的欄位（id、角色名），重新執行 `fetch-data` 也不會受影響。

*部分功能與資料 fork 自 beymetchannel/PlakoroBattle，特此感謝 beymetchannel 開源

# 待處理 issue
- 招式機率的「參與擲骰」總次數上限目前為 9（6^9 ≈ 1000 萬種組合），實測會耗用約 4GB 記憶體，在手機瀏覽器會導致分頁崩潰；需降低上限或改為不展開全部組合的計算方式
- 爬塔模式的寶可夢卡片未顯示弱點屬性（傷害計算正確，僅未顯示）
- 資料已支援雙弱點（`weakness_type2`），但資料庫目前所有寶可夢皆只有單一弱點，尚未有實際案例可驗證
- `diceParts.js` 的 `randomDualChip()` 用 `pickTwoDistinct`，產不出同色雙晶片；實體商品確實有同色雙晶片（例如小火龍 02 內含 5 片火＋火），所以組骰頁的初始骰組永遠不會出現最強的純屬配置
- 商品內容物僅涵蓋已公布並清點過的 16 款；進化套組、太晶套組與啟程 10-14 官方尚未公布內容，購入零件不會把它們算進去
